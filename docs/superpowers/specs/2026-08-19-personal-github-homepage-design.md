# Milo 个人 GitHub 主页设计

- 日期：2026-08-19
- 状态：已确认
- 目标仓库：`Minglu-Li.github.io`
- 目标地址：`https://minglu-li.github.io/`

## 1. 背景与目标

Milo 是一名专注 AI Agent 应用的全栈开发者，擅长把复杂想法做成可靠、真正能用的产品。主页需要同时承担求职、项目展示和个人品牌三种职责，其中招聘方与潜在雇主是第一受众，潜在客户、合作伙伴和开发者同行是第二受众。

页面的首要任务是让招聘方在十秒内理解 Milo 的专业定位，并能继续查看代表项目、精简经历、可下载简历和联系方式。技术关键词用于证明工程与研究深度，不作为首屏主体。

## 2. 设计原则

1. 先给结论，再给证据。首屏说明 Milo 是谁和能解决什么问题，随后依次展示项目、实习、能力与联系方式。
2. 展示可交付能力，而不是堆叠技术标签。项目文案以问题、决策、实现和结果为主。
3. 使用真实内容。没有资料的项目、经历、邮箱或简历入口整体隐藏，不发布虚构案例或空白卡片。
4. 双语共享同一信息架构。中英文切换不改变页面顺序，也不产生明显布局跳动。
5. 视觉大胆处只保留一个。“构建轨迹”是全站唯一的标志性图形与主动画，其余界面保持克制。

## 3. 范围

### 3.1 本期包含

- Vue 3、Vite 和 TypeScript 构建的响应式单页主页。
- 中文与英文内容切换，并记住访客选择。
- 首屏定位、构建轨迹、代表项目、实习经历、能力地图和联系区。
- 项目、经历、邮箱、简历与头像的可选内容状态。
- 两份独立的中英文 PDF 简历入口。
- GitHub Pages 自动构建与发布流程。
- SEO、Open Graph、favicon、键盘访问和减少动态效果支持。
- 单元测试、组件测试、端到端测试和生产构建验证。

### 3.2 本期不包含

- 博客、内容管理后台或数据库。
- 运行时 GitHub API 请求。
- 服务端渲染、后端接口、联系表单或访问统计。
- 独立项目详情路由；项目可以链接到 GitHub、在线演示或外部详情页。
- 自动翻译。所有公开文案均由明确的中英文内容字段提供。

## 4. 内容策略

### 4.1 核心定位

中文主张：

> 把复杂想法做成可靠、能用的产品。

英文主张：

> I turn complex ideas into reliable, usable products.

辅助身份为“AI Agent 应用开发者 / 全栈工程师”。首屏说明聚焦模型、系统与真实用户之间的连接，不使用夸张的营销语言。

### 4.2 内容优先级

1. **代表项目**：证明独立判断、AI Agent 能力和端到端交付。
2. **精简经历**：证明在团队环境中的协作与稳定交付。
3. **能力地图**：补齐招聘筛选所需技术关键词。
4. **完整简历**：通过 PDF 提供更详细信息。
5. **联系方式**：为招聘、合作与技术交流提供明确下一步。

### 4.3 能力分组

- Agent Systems：AI Agent、LLM、NLP、强化学习。
- Full-stack Delivery：Java、Spring、TypeScript、Python、数据库、云部署。
- Applied AI & Domain：图神经网络、电力系统、人工智能应用。

### 4.4 当前内容状态

已确认并可公开的信息包括 Milo 的姓名、专业定位、技能方向和 GitHub 主页 `https://github.com/Minglu-Li`。

项目案例、两段实习的详细文案、邮箱、头像文件以及中英文 PDF 简历在本期实现开始时没有配置。实现必须完整提供这些内容类型和视觉组件，但默认不渲染缺少真实数据的区块或入口：

- 项目列表为空时隐藏项目区和项目导航；首屏主按钮改为“访问 GitHub”。
- 实习列表为空时隐藏经历区和经历导航。
- 简历 URL 为空时隐藏简历按钮。
- 邮箱为空时隐藏邮件按钮和独立联系区，保留 GitHub 联系入口。
- 头像为空或加载失败时显示 `ML` 字母头像。

补充资料只需要更新内容配置和 `public` 资源，不修改页面组件。

## 5. 信息架构

页面按以下顺序组织：

1. **固定导航**：Milo 标识、项目、经历、能力、联系、GitHub 和语言切换。没有对应内容的导航项隐藏。
2. **Hero 首屏**：身份标签、核心主张、简短说明、主要 CTA、次要 CTA 和头像。
3. **Build Trace 构建轨迹**：`IDEA → AGENT → BUILD → SHIP`，说明从理解问题到可靠交付的工作方式。
4. **Selected Work 代表项目**：2–4 个精选案例，首个主案例拥有更大视觉面积。
5. **Experience 实习经历**：按时间排列的两段经历，强调职责、协作和结果。
6. **How I Build 能力地图**：以三个能力分组呈现关键词，不使用无层级的标签墙。
7. **Contact 联系区**：简洁邀请语、邮件 CTA、GitHub 和简历入口。
8. **页脚**：姓名、版权信息和语言状态。

## 6. 视觉系统

### 6.1 方向

采用已确认的“构建轨迹 / Build Trace”方向。页面借用工程蓝图和系统执行轨迹的视觉语言，表达把抽象想法转化为可运行产品的过程。它应显得冷静、清晰、可信，而不是像通用的深色终端模板或 AI 营销页。

### 6.2 色彩

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 工程墨 | `#14213D` | 主文字、深色轨迹区、页脚 |
| 电路蓝 | `#245FD4` | CTA、焦点、主要链接和轨迹节点 |
| 信号蓝 | `#8FB6FF` | 次级强调、选中与状态反馈 |
| 蓝图冰 | `#EEF4FF` | Hero 与浅色结构背景 |
| 界面白 | `#FBFCFF` | 正文背景与内容卡片 |

所有正文、控件和交互状态必须满足 WCAG AA 对比度要求。

### 6.3 字体

- 英文展示字体：Instrument Sans。
- 中文与正文：Noto Sans SC，使用系统中文无衬线字体作为回退。
- 工程标签与状态：IBM Plex Mono，使用系统等宽字体作为回退。

字体以经过裁剪的本地 Web Font 资源提供，加载失败时回退字体不得造成明显布局错位。

### 6.4 布局

- 桌面端最大内容宽度约 1180px，使用 12 列网格。
- Hero 使用非对称双栏布局，文案约占 7 列，头像或品牌图形约占 5 列。
- 项目区首个案例较大，其余案例使用紧凑卡片。
- 移动端改为单列；导航收敛为可键盘操作的菜单；CTA 使用完整触控宽度。
- 蓝图网格只用于 Hero，不扩散到所有区块。

### 6.5 动效

页面首次进入时，构建轨迹的四个节点在约一秒内依次点亮。该动画完成后保持静止。项目卡仅使用轻微的位移或边框反馈，不使用全页滚动飞入效果。

当系统启用 `prefers-reduced-motion: reduce` 时，所有非必要动画立即显示最终状态。

## 7. 技术架构

### 7.1 工程结构

```text
src/
├─ components/
│  ├─ SiteHeader.vue
│  ├─ HeroSection.vue
│  ├─ BuildTrace.vue
│  ├─ ProjectsSection.vue
│  ├─ ExperienceSection.vue
│  ├─ CapabilitiesSection.vue
│  └─ ContactSection.vue
├─ composables/
│  └─ useLocale.ts
├─ content/
│  ├─ profile.ts
│  └─ types.ts
├─ styles/
│  ├─ tokens.css
│  ├─ base.css
│  └─ motion.css
├─ App.vue
└─ main.ts

public/
├─ portrait.*
├─ resume-zh.pdf
├─ resume-en.pdf
├─ favicon.*
└─ og-image.*
```

单页使用锚点导航，不引入 Vue Router。所有公开内容从类型安全的 `profile.ts` 导出，各区块只负责渲染，不在组件内部维护重复文案。

### 7.2 内容模型

内容模型包含以下主要类型：

- `LocalizedText`：必需的 `zh` 与 `en` 字段。
- `Profile`：姓名、身份、简介、GitHub、可选邮箱、可选头像和可选简历路径。
- `Project`：标识、名称、摘要、问题、贡献、结果、技术、仓库、演示和可选图片。
- `Experience`：公司、岗位、起止时间、摘要和成果列表。
- `CapabilityGroup`：分组名称、说明与技术条目。

项目与经历数组允许为空。类型与测试共同保证已存在的项目或经历同时具有中英文公开文案。

### 7.3 语言状态

语言选择优先级如下：

1. `localStorage` 中上次保存的合法选择。
2. 浏览器首选语言，以 `zh` 开头时使用中文，否则使用英文。
3. 无法读取浏览器设置时使用中文。

切换语言时同步更新：

- 页面可见文案；
- `<html lang>`；
- `document.title`；
- description 和 Open Graph 文案；
- 当前语言对应的简历链接。

本地存储读写失败不影响页面，语言状态退回当前会话内存。

### 7.4 数据流

```text
浏览器偏好 / 已保存选择
            ↓
        useLocale
            ↓
     当前语言 + profile
            ↓
 Hero / Projects / Experience / Capabilities / Contact
```

页面不在运行时请求 GitHub API。项目数据由 Milo 手工筛选和撰写，以保证内容稳定、结果导向并避免限流或网络故障。

## 8. 降级与错误处理

- 头像资源不存在或加载失败时显示 `ML` 字母头像。
- 项目图片不存在时显示带有构建轨迹的蓝图封面。
- 缺少可选内容时隐藏整个入口或区块，不显示禁用按钮。
- 配置了本地简历或图片路径但资源不存在时，自动化测试使 CI 失败。
- 外部链接使用安全的新窗口属性；无效 URL 在内容测试阶段报告。
- 字体资源失败时使用定义好的系统回退字体。
- 页面没有运行时 API 和服务端状态，因此主体内容不受第三方服务可用性影响。

## 9. SEO、隐私与可访问性

- 使用语义化 `header`、`nav`、`main`、`section`、`footer` 和连续标题层级。
- 为头像、项目图片和图标提供有意义的替代文本；纯装饰元素从辅助技术中隐藏。
- 所有交互可使用键盘完成，并具有清晰的 `:focus-visible` 样式。
- 触控目标不小于 44px，正文和控件满足 WCAG AA 对比度。
- 语言切换使用可识别的按钮状态，而不是只依靠颜色。
- 配置 title、description、canonical、Open Graph 和 favicon。
- 默认不加载分析、广告、Cookie 或访客追踪脚本。

## 10. 部署

目标仓库为 `Minglu-Li.github.io`，Vite 的 `base` 使用 `/`。GitHub Actions 在 `main` 分支推送后执行以下流程：

1. 安装锁定依赖。
2. 执行类型检查、单元测试和组件测试。
3. 执行生产构建。
4. 执行端到端冒烟测试或等价的生产预览检查。
5. 上传 `dist` 并发布到 GitHub Pages。

任一检查失败时不发布新版本。

## 11. 测试与验收标准

### 11.1 自动化测试

- Vitest 覆盖语言选择优先级、非法存储值回退、内容回退、空模块隐藏和链接生成。
- Vue Test Utils 覆盖 Hero CTA、导航可见性、语言切换和各内容区块。
- Playwright 覆盖桌面与移动端页面、锚点导航、菜单、键盘操作、GitHub 链接、简历链接和邮件链接。
- 内容完整性测试验证双语字段、本地资源路径和外部 URL。

### 11.2 发布前命令

- `npm run type-check`
- `npm test`
- `npm run build`
- `npm run test:e2e`

### 11.3 验收结果

- 中文与英文切换正确且选择可记忆。
- 从 320px 移动端到桌面宽度均无横向溢出。
- 键盘可以访问导航、语言切换和所有 CTA。
- 减少动态效果模式下没有非必要动画。
- 没有配置的内容不会产生空白区、错误链接或破图。
- 生产构建可在 GitHub Pages 根路径正常加载所有资源。
- Lighthouse 的性能、可访问性、最佳实践和 SEO 四项均达到 90 分或以上。
